# 范文库（Few-shot 风格范例）

这里放你收集的优质软文。生成时，系统会按「平台 + 人群 + 场景」检索最匹配的 1–2 篇，作为**风格范例**注入模型——只让模型学**语气、结构和节奏**，**不抄句子、不借事实**（产品参数永远只来自 P1）。

## 怎么加一篇范文

在本目录下新建一个 `.md` 文件（文件名随意，建议 `平台-人群-场景-简述.md`），开头写 frontmatter，再写正文：

```markdown
---
platform: 小红书          # 必填，须与发布平台枚举一致，决定能否命中
perspective: 真实用户      # 选填，写作视角，命中加分（真实用户 / 官方宣传 / 媒体报道 / 行业分析）
product: MateBook D 14    # 选填，记录这篇范文描述的是哪个产品；没有明确对应就写 无明确
audience: 大学新生         # 选填，人群关键词，命中加分；没有明确对应就写 无明确
scene: 开学季             # 选填，业务场景，命中加分；没有明确对应就写 无明确
tags: [轻薄, 续航, 宿舍]   # 选填，关键词命中各加分
good_points: 开头用具体场景切入；每段一个痛点配一个动作；短句多、口语自然；结尾抛问题引互动
---

（范文正文，纯风格参考，不要写死某台机器的具体参数或价格）
```

## 字段与匹配规则

- `platform`：**硬门槛**。只有平台一致（或范文不写平台 = 通用）才会被选中，避免拿公众号范文去教小红书。
- `perspective`：写作视角（真实用户 / 官方宣传 / 媒体报道 / 行业分析）。命中加分，帮助检索到立场一致的范文。建议每篇都打上。
- `product`：这篇范文描述的产品，仅作记录与展示（不参与打分，避免诱导模型照搬同款产品的参数）。没有明确对应就写 `无明确`。
- `scene` / `audience`：命中加分。没有明确对应的范文写 `无明确`，这样会在"人群/场景留空的通用软文"里被优先选中。
- `tags`：关键词命中各加分，排序后取前 1–2 篇。
- `good_points`：一句话点评"这篇好在哪"，等于直接告诉模型要学什么——**强烈建议写**，比正文本身还重要。
- 正文：只提供写法。不要写死要推的那台机器的参数/价格，事实由 P1 负责，否则模型可能把范文里的数字当成本机参数。

## 说明

- 目录为空也不影响运行：没有命中的范文时，模型按平台模板正常生成。
- 平台名必须和系统枚举对齐（小红书、微信公众号、销售朋友圈、知乎、微博、门店海报、新闻稿、抖音短视频、微信视频号、B站中长视频、短视频口播、直播讲解、企业采购方案）。
- 可用环境变量 `EXEMPLAR_ROOT` 指定其他目录，默认是项目根下的 `范文库/`。
