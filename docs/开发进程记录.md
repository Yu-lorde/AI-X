# 开发进程记录

本文档按时间顺序记录开发过程中发现的问题、修正方案与优化效果，供赛后复盘与迭代参考。每条记录包含：现象 → 根因 → 解决方案（改动概述 + 文件）→ 背后逻辑 → 效果。

## 记录 001 · 2026-10-21 · 一句话需求解析

**需求**：网页开头支持一句话输入，自动映射出型号 / 人群 / 场景 / 平台，额外要求并入本次生成。

**方案概述**：新增 `agent/parse_request.py`，用 LLM 把一句话抽成结构字段，场景/平台严格限定在现有枚举内（选不出留空），型号只抽不编，额外要求并入 `note`；`agent/app.py` 顶部加「一句话需求」框 +「解析填入」按钮，解析后回填可改表单，两步走再生成；缺字段沿用追问机制，无 `LLM_API_KEY` 时提示改用表单。

**效果**：从"逐项选择/填写"降为"一句话 + 核对"，保留了人工校正环节与原有追问兜底。

## 记录 002 · 2026-10-21 · 成稿「合规纪律泄漏 + 产品事实缺失」修正

### 一、现象

以「MateBook D 14 / 大学新生 / 开学季 / 小红书」生成的成稿，读起来不像软文，更像"一个助手在向用户汇报它查到了什么、不敢说什么"。典型句子：

- "官方公开定位写的是13代酷睿、护眼屏、全功能USB-C、超级终端。就这些，别的配置我没拿到确切信息，不瞎写。"
- "屏幕具体亮度、分辨率这些数字，资料里没给，我不编。"
- "官网参考起价是¥5,799，但这个价格是官网参考，具体以华为商城当前展示和结算页为准。而且我查的时候，华为商城原商品页显示已下架。"

### 二、发现的问题（两层叠加）

**问题一：产品事实没有喂进模型（主因）。**
成稿声称"亮度、分辨率资料没给"，但本地 P1 `产品事实.md` 里白纸黑字有 14 英寸、1920×1200、300 尼特、100% sRGB（标准版）、16:10、1.39 kg、56 Wh、i5-13420H、USB-C/两个 USB-A/HDMI 等完整参数。模型这一轮拿到的只是一段稀薄的"定位话术"。

根因：本次走远程 ima 知识库，`read_media` 读不到正文时会**静默回落到检索摘要片段**（highlight 短句）。这些稀料非空，于是完整性判断 `_pack_incomplete` 认为"资料够了"，永远不触发本地知识库兜底——而本地恰好有完整参数。没有具体数字，模型只能写空泛形容词，并用"资料没给我不编"来填满篇幅。

**问题二：合规纪律暴露在正文腔调里。**
系统 Prompt 的"不许编"本意是内部约束（没依据的别写、丢进 pending），但模型把它理解成"要向读者解释自己为什么不写、哪里不确定"，于是满屏免责声明与元话术（"我不编""以官网为准""已下架""官方定位里写的是…"）。叠加问题一，整篇变成一份带免责声明的检索汇报。

### 三、解决方案（改动概述 + 文件）

采用一套跨场景、跨平台通用的"通法"，不针对单一平台语言风格，分 4 处配套修改：

| # | 改动概述 | 文件与位置 |
|---|---------|-----------|
| 1 | 给远程事实记录打标 `from_highlight`（是否只拿到摘要、没拿到正文） | `agent/pipeline.py` `_collect_sources` |
| 2 | 当所有事实文档都只有摘要、没有实质正文时判为"不完整"，触发本地知识库兜底（读到完整 `产品事实.md`） | `agent/pipeline.py` `_pack_incomplete` |
| 3 | 喂给模型的事实摘录上限从 1500 字提到 3000 字，避免参数被截断在屏幕规格之前 | `agent/pipeline.py` `_user_prompt` |
| 4 | 系统 Prompt 新增「正文表达纪律」：证据边界只决定"写什么"不决定"怎么说"；正文禁免责声明、元话术、来源归因；不确定项只进 pending；尽量把具体参数自然落进正文 | `agent/prompts.py` `SYSTEM_PROMPT` |
| 5 | 新增「元话术 / 免责声明」检测器（词表 + 正则），命中即触发现有重写闭环删除 | `agent/humanizer.py` `META_DISCLAIMER_WORDS` / `META_DISCLAIMER_RE` / `check_style` |
| 6 | 重写指令明确：正文里的免责声明、元话术和来源归因一律删除，不要改写保留 | `agent/pipeline.py` `_rewrite` |

### 四、方案背后的逻辑

- **问题一是数据链路 bug，不是文笔问题。** 软文的"真实感"来自具体（"300 尼特、1.39 kg"像真的，"护眼屏、轻薄"像广告词）。所以第一优先级是把料送到模型嘴边——复用已有的本地兜底通道，只是把触发条件从"远程完全没返回"收紧到"远程没返回实质正文"。改动面最小、最通用。
- **问题二要区分"内部纪律"与"读者可见"。** 不编造是对的，但那是生成时的取舍，不该写给读者看。于是双保险：Prompt 从正面约束（纪律 2/4），humanizer 从负面拦截（规则 3/5/6）——即使模型偷懒泄漏，也会被现有"生成→核验→重写"闭环逮回去删掉。
- **只改措辞与取数，不碰主干。** 场景路由、P8/P6/P1 职责分离、核验主干、平台模板逻辑一律不动；本地兜底仍只喂 `产品事实.md` 原始参数，不喂语气偏谨慎的 `卖点与限制.md`，避免把分析腔再带进来。

### 五、实现的效果优化

- **参数进正文**：模型拿到完整 P1 后，正文能落具体数字（尺寸、重量、屏幕、接口、电池等），不再靠空泛形容词和"资料没给"填充。
- **腔调去质检化**：免责声明、元话术、来源归因被 Prompt 禁止 + 检测器拦截 + 重写删除，成稿从"汇报检索过程"回到"直接出稿"。
- **离线验证**：问题样本命中 1 条元话术告警（覆盖"我这次看的/资料没给/官网参考/已下架/官方定位"等）；方向 A 的干净改写元话术 0 命中、humanizer 全项通过。`py_compile` 与 `test_core.py` 均通过。

### 六、遗留与后续

- 本次只解决"合规泄漏 + 事实缺失"的通法，**未做**平台/人群/场景的语言风格适配（下一阶段议题，候选方案：few-shot 范文检索 + 评测闭环，详见后续记录）。
- 元话术词表/正则为保守命中，后续可随 bad case 增补。

## 记录 003 · 2026-10-22 · 风格适配（few-shot 范文库 + 视角 + 通用模式）

本轮为"方向 A"的风格适配打底，做了四件事（设计讨论结论：先 few-shot 范文、不自训模型）。

**① Few-shot 范文库**：新增 `agent/exemplars.py` + 项目根 `范文库/`。生成时按「平台+视角+场景+人群」检索最匹配的 1–2 篇范文注入 prompt，只学语气/结构/节奏，严禁照抄句子或借用其产品信息。平台是硬门槛。

**② 写作视角 perspective**：`strategy.py` 定义 4 个枚举（真实用户/官方宣传/媒体报道/行业分析），界面加下拉框、一句话解析可识别；视角带一段立场说明进 prompt，且"真实用户"≠允许编造体验（合规不变）。

**③ 人群/场景可选 + 通用模式**：`missing_questions` 只强制型号和平台；人群留空或场景选「无明确」时走 `generic_route`，跳过 P8 行业路由，按通用产品软文生成（平台模板 + P1 + 视角 + 范文）。

**④ 范文每篇加 `product` 字段**：记录该范文描述的产品，仅展示不参与打分。

改动文件：`agent/exemplars.py`（新增）、`strategy.py`、`scenario_router.py`、`pipeline.py`、`parse_request.py`、`app.py`、`local_kb.py`、`prompts.py`、`范文库/`。

**范文库规范化**：4 个来源拼入的 ~80 篇格式互不兼容（无围栏/转义键/平台值对不上枚举），几乎全部检索不到。用一次性脚本统一成标准 fenced frontmatter、平台/视角/场景按关键词归一到枚举、移出 5 个非范文索引文件。规范化后 81 篇全部可加载命中（销售朋友圈 24／微信公众号 24／抖音短视频 21／小红书 12）。

## 记录 004 · 2026-10-22 · 参数安全 + 价格卡根因 + 误报修复（含真实自测）

### 一、需求

范文里带有大量**其他机型**的参数（如 MateBook 14 鸿蒙版的 2.8K OLED / 70Wh / 120Hz）。要求：实际成稿里用到的参数**必须严格来自 P1 知识库**，绝不能从范文搬运。

### 二、做了什么（改动概述 + 文件）

| # | 改动 | 文件 |
|---|------|------|
| 1 | 新增**参数核验闸**：扫描成稿中"数字+单位"参数（尼特/Wh/GB/TB/Hz/英寸/kg/mm/ppi/K/%/W 等），凡在 P1 原文找不到对应数字即判违规，进重写闭环删除/订正 | `compliance.py` `SPEC_RE` |
| 2 | prompt 补充：范文多描述别的机型，其参数（2.8K/OLED/70Wh/处理器型号等）绝不能搬进成稿，成稿每个参数都要能在 P1 找到 | `prompts.py` |
| 3 | **根因修复**：把"价格"移出 `FACT_HINTS`、加入 `REJECT_HINTS`，`价格卡.md` 不再被当作产品事实喂给模型 | `strategy.py` |
| 4 | 误报修复：`100%`（误伤 100% sRGB）从绝对化词表移除；`第一`改为仅排名断言才判（"开学第一周"不再误报）；价格数字比对去千分位（`5799` 对上 `5,799`） | `compliance.py` |
| 5 | 误报修复：营销词若在 P1 原文本就存在（如官方功能名"一键还原"），不计 AI 腔；`check_style` 增加 `source_text` 入参 | `humanizer.py`、`pipeline.py` |

### 三、根因（为什么之前仍"不像软文、满屏价格"）

真实自测发现：三个用例的事实点**全部来自 `价格卡.md`**（内容是"已下架/参考价¥5799/13代酷睿·护眼屏"的价格口径 + 空泛定位），而带 300 尼特/1.39kg/56Wh 的 `产品事实.md` 根本没进来。原因是"价格"在 `FACT_HINTS` 里 → `价格卡.md` 被当成产品事实文档，且它有正文（非摘要），连带记录 002 的"稀料兜底"也不触发。移除后，若远程只返回价格卡则判为资料不完整 → 自动回退本地 `产品事实.md`，真参数得以进入成稿。

### 四、实现的效果（真实生成自测）

- **用例1（D14/大学新生/开学季/小红书/真实用户）**：成稿落满 P1 实参数（1.39kg、14 英寸、1920×1200、i5-13420H、16GB、512GB、56Wh、65W、USB-C/USB-A×2/HDMI、背光键盘 1.5mm 键程、指纹电源键），全部回链 `产品事实.md`；价格免责段消失；**合规 0 问题**。
- **用例2（空人群/无明确/公众号/媒体报道）**：通用模式生效，写成"标准版 vs SE 版色域、Windows vs Linux 差异"的媒体稿，全是 P1 实参数。
- `test_core.py` 增加参数泄漏测试并通过。

### 五、遗留与后续

- **远程 ima 共享库似乎只返回 `价格卡`、缺 `产品事实` 文档**，两个用例最终都靠**本地回退**拿到规格（`source=本地知识库`）。要让远程也好用，需把 `产品事实/规格` 文档补进 ima 库并建索引（数据问题，非代码）。
- 价格现被完全排除在事实外；若以后要让成稿带**干净价格**，应单独做"价格字段"而非混入价格卡。
- `三词并列` 启发式偶有误报（如"一个、一个、又一个"），影响很小，暂留。
- 参数核验闸只覆盖"数字+单位"；型号名泄漏（如"酷睿 Ultra 7"）仍主要靠 prompt 约束。
