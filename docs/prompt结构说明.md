# 生成 prompt 的拼装结构

本文件说明：智能体产出一篇软文时，喂给大模型的 prompt 是怎么拼出来的、每块材料负责什么。对应代码在 [`agent/pipeline.py`](../agent/pipeline.py) 的 `_user_prompt()` 与 [`agent/prompts.py`](../agent/prompts.py) 的 `SYSTEM_PROMPT`。

资料全部来自工作区的 `知识库/` 文件夹（产品 / 画像 / 平台模板），不再走远程。

## 一、两段式消息

- **system（固定）= `SYSTEM_PROMPT`**：职责分离铁律、合规、正文表达纪律、反 AI 腔（含结构反 AI）、参考范文规则、输出 JSON 契约。
- **user（每次拼装）= `_user_prompt()`**：把本次任务的材料按下面的顺序组装。

## 二、user prompt 的拼装顺序

```
① 任务头      型号 · 人群 · 场景 · 写作视角(+立场说明) · 发布平台 · 临时修改要求
② 参考范文    按「平台(硬门槛)+视角+场景+人群」从 范文库/ 检索最匹配 1–2 篇
                → 只学语气/结构/节奏；严禁照抄句子、严禁借用范文里的产品参数
③ 平台模板    知识库/平台模板/<平台>.md（精简版：写作流程 / 字数 / 图文节奏 / 标题数 / 交付字段）
④ 客户画像    知识库/画像/<模块>.md（有就放，理解人群角色/任务/限制；
                没对上画像时这里为空，改为“按你对人群的理解来写”）
⑤ 产品事实    知识库/产品/<型号>/产品事实.md —— 唯一的参数/型号/功能来源
⑥ 图片清单    只能用本型号、知识库里有的图片
```

## 三、职责分离铁律（整个参考逻辑的核心）

| 材料 | 只负责 | 绝不负责 |
|------|--------|---------|
| 客户画像 | 理解人群的角色、任务、门槛 | 不提供产品参数；画像没确认的门槛不能写成已满足 |
| 产品事实 | 写什么事实（参数/功能/型号/价格） | 不管语气和结构 |
| 平台模板 | 写成什么形态（流程/篇幅/节奏/标题数/字段） | —— |
| 参考范文 | 什么语气/结构/节奏 | **不借它的产品信息，不照抄它的句子** |
| 写作视角 | 站在什么立场（真实用户/官方/媒体/行业） | 不突破合规 |

一句话：**参数只认产品事实，风格只学范文，形态只随平台模板，人群理解靠画像（或模型自身理解），立场由视角定。**

## 四、映射与兜底

- **一句话解析**（`parse_request.py`）：能对上枚举的（平台、场景）就映射；对不上的，模型从原话抽出要素和额外要求，填进页面表单（场景放不进就并入"临时修改要求"）。
- **未知人群**：画像库里没有对应画像时，不追问，直接让模型按自己对该人群的理解来写（但不得编造未证实的使用结论）。
- **通用模式**：人群留空或场景选「无明确」→ 不绑定画像，按通用产品软文写。
- **未知产品**：知识库没有该型号时，目前停下提示；后续计划接入联网查官网补参数（见开发进程记录）。

## 五、产出后的核验闭环

模型吐 JSON → 归一化 → 核验：

- **合规**（`compliance.py`）：参数必须能在产品事实里找到对应数字（按完整数字比对，防止从范文搬别的机型参数）、价格、绝对化、虚假体验。
- **AI 味**（`humanizer.py`）：营销套词、元话术/免责声明、来源归因、逐项罗列、三词并列、口水词、句长方差等。

命中就带着问题重写，**最多 3 轮**，直到通过或到上限；每条事实回链产品事实标题比对；清不掉的残留进"待确认"。
